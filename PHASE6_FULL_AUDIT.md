## Static safety and backend readiness

PASS code/regression checks: no fetch/axios/backend integration in src; no raw HTML injection; localStorage confined to sanitized cart/wishlist/explicit PIN preferences. No session/address/order persistence. No actual OTP/payment verification, fabricated public prices/stock/reviews, or added credentials. Admin remains explicitly an unsecured static preview. Fixture routes/data are excluded from production bundle by existing tests.

CMS/catalogue edits disappear on refresh; file previews are temporary object URLs. Compliance format validation is not official verification. Demo publication is not a real public publishing action.

Before real deployment/backend work:
- Require server authentication/authorization and customer ownership; client guards are not security.
- Enforce price/stock/status, order transitions, idempotency and inventory transactions on the server.
- Use one authoritative order/event model; protect internal notes and personal data.
- Add durable media upload/type scanning, protected storage, revision/version control and server publication filters.
- Keep payment secrets on the backend; no frontend credentials.
- Reconcile API mutations through existing service boundaries; avoid duplicate presentation stores.
- Configure SPA fallback and production security policies.
- Complete per-page SEO/meta/canonical behavior; current SEO integration is partial.
- Integrate reviewed delivery/tax/minimum/COD rules; stored settings deliberately do not turn the isolated fixture into live checkout.
