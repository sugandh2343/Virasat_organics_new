# Virasat Organics v2

React + Vite storefront and administration frontend with a private PHP/MySQL backend. Includes Firebase customer authentication, CMS/media management and guarded COD commerce. See PHASE7H_FINAL_AUDIT.md and ADMIN_MEDIA_UPLOAD.md for implementation status and pending live acceptance checks.

## Local development
Requires Node.js 22.12+ (tested with 24.18) and npm.

```sh
npm install
npm run dev
```

Open the Local URL printed by Vite (normally http://localhost:5173).
Production check: `npm run build`. Preview the build: `npm run preview`.

## Structure
- src/components — reusable brand, header and footer
- src/layouts — shared route layout
- src/pages — minimal home, collection, product and information shells; 404
- src/styles — responsive global design tokens and styles
- src/mock-data — products, navigation, business information, homepage copy
- src/assets — original temporary editorial SVG; no actual packaging photographs
- src/services — asynchronous mock catalogue boundary for a future API

Routes: /, /shop, /shop/:slug, /our-roots, /our-story, /journal, /contact.
No checkout, customer panel, admin panel, cart, payment or backend integration.

## Data conventions
The five products are independent records with no variants.
SKU values prefixed DEMO are temporary internal identifiers.
price, compareAtPrice and stock are null until verified; null is not zero.
All products start as coming_soon. Supported statuses: active, inactive,
out_of_stock, coming_soon. Inactive products are excluded by the service.
images and videos are empty arrays pending approved assets.
Ingredients and specifications remain empty rather than making unsupported claims.
SEO is reserved in each product record for a future metadata implementation.
Business contact details remain null pending confirmation.

The supplied screenshot is visual direction only. The text-based brand treatment
and editorial SVG are temporary design elements, not approved brand artwork or
actual product packaging. Google Fonts are optional; local serif/sans-serif
fallbacks keep the site usable offline.

Future static hosting must rewrite unknown application routes to index.html.
No deployment or Git commit was performed.

### Usage contracts
Import components from src/components/ui/index.js. Buttons accept standard
button props; PrimaryButton/SecondaryButton also accept to or href for links.
Disabled links render disabled buttons. IconButton requires a descriptive label.
Container supports as and className. SectionHeading accepts eyebrow, title,
description, as (heading level), and an optional action as children.

ProductCard accepts product, onAddToCart, onWishlist and wishlisted. Callbacks
are extension points only: no cart or wishlist storage is implemented.
Inactive cards render nothing. Coming-soon/out-of-stock cards cannot be
purchased. Active cards require a finite non-negative numeric price and positive
integer stock. An active product with zero stock displays Out of stock.
Unconfigured active products use Coming soon. Without onAddToCart, an otherwise
available product shows disabled Shopping coming soon. No variants are created.
PriceDisplay accepts price, compareAtPrice and currency (INR default).
MRP appears only when valid and greater than price; missing prices never become 0.
RatingDisplay defaults to No ratings yet. Only pass verified value/count, or use
demo=true to label an explicitly illustrative presentation.

Images may be URL strings or objects { src, alt, srcSet, sizes }. ResponsiveImage
supports aspectRatio, fit (contain/cover), loading and descriptive alt.
ProductGallery supports any number of images with keyboard-operable thumbnails;
ProductCard supports an alternate second image on pointer hover.
The gallery preview intentionally repeats the existing illustration to demonstrate
selection; it is not a second product photograph. One intentionally malformed
inline image demonstrates the broken-image fallback without a network request.

ModalShell/DrawerShell accept open, onClose, title, description, children and
footer. Use controlled React state. Native dialog provides modal focus containment
and background inertness; Escape/backdrop/close buttons invoke onClose. Closing
restores the opening control's focus and releases the body scroll lock.
Keep overlays within the same document and use current browsers supporting dialog.

### Responsive and accessibility guidance
Mobile is the base; tablet starts at 48rem, desktop at 64rem.
Cards use 1/2/3 columns respectively. Interactive controls have at least 44px
touch targets, visible keyboard focus and reduced-motion overrides.
Use semantic darker text tokens on light surfaces; gold/olive remain accents.
Heading levels can be selected with SectionHeading's as prop.
