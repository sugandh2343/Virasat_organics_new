## Adapter rules and presentation gaps

Retain ProductCard, CategoryCard, ProductInformation, filters, overlays, editor controls, layouts and CSS. Minimal wiring changes are necessary for real authentication loading/expiry, async writes, provider payment UI and server error fields; preserving UI is not a promise of zero code changes.

Use API envelope unwrapping at service layer, explicit 404→null for detail, throw typed validation/conflict errors otherwise. Never silently fall back to mock data when production API fails. Loading/error/empty components already exist. Protected data must be evicted on logout/401; in-flight responses tied to prior principal discarded. Public cache can remain.

Current services export synchronous session transforms; future calls are asynchronous. Do not put network calls in reducers. Components dispatch pending/success/error after adapters settle; server order confirmation comes before cart clear. On timeout retry same key; don't clear cart until confirmed. Preserve idempotency key across retry but not across edited cart/quote.

Current pages can assume full arrays. Server pagination requires total/count metadata and bounded admin/shop pages; search/filter must run on server before pagination. Related products can query category excluding current ID (or adapter exclude and fetch sufficient page). Homepage collection fetches original configured order, not arbitrary newest five.

No production import of empty mock customer arrays as live state. No persistent blob URLs, dummy session IDs or DEMO order references. API order snapshots supply historical SKU/name/size even if catalogue changes. Existing map link remains explicit confirmed coordinates; no Google Maps API is planned.

Stop conditions: do not enable real checkout without configured tax/shipping/prices/stock and backend acceptance tests; do not expose authenticated admin mutations before7A RBAC; do not enable Razorpay before7E signed events/reconciliation tests.
